# MCP Hub 界面：配置库优先

本文件描述 v0.4.0 的正式 GUI；历史 `ui-workbench.html` 是演示原型，不连接真实配置。

## 用户任务与页面职责

用户先维护一份 MCP 库，再选择目标 Agent，核对影响后应用。页面不要求用户先理解文件格式或十四列矩阵。

- **我的 MCP**：默认页面。查看、搜索、添加和编辑全部条目，点「选择目标」打开详情，勾选每项独立的目标 Agent。
- **Agents**：只读查看 Agent 原生配置，明确来源路径；通过独立导入流程将条目带回库中。
- **变更历史**：核对当次写入结果，查看备份涉及文件，明确确认后恢复。
- **软件设置**：侧栏底部入口，保存启动默认库、备份目录、默认范围和策略。软件设置与 Agent 的全局配置不同。

添加、编辑、配置库位置、项目目录、批量矩阵、预览都使用任务对话框。分发预览不占主导航。
每个对话框只负责一件事，写入过程中锁定上下文；未保存的编辑在取消、Escape 或切页时要求明确放弃。
原生 dialog 限制焦点进入背景，提供可访问名称和关闭按钮，窄窗口仍可滚动到操作栏。

## 主流程

1. 空库显示「从已有 Agent 导入 / 手动添加 / 打开已有配置库」。不存在的库是正常首次使用状态，读取不会创建文件。
2. 保存配置只更新配置库，不自动分发。参数逐项、键值逐行，保留逗号、等号、空格和空参数。
3. 点选 MCP 后显示详情与目标。已检测到的 Agent 优先展示，其余可展开；不匹配的范围和不支持目标明确说明原因。
4. 出现底部选择栏后进入预览。逐文件显示真实路径、新增/更新/保持数量、阻止/跳过/共享文件提示，差异可展开。
5. 确认后显示逐项结果，区分配置已写入、部分失败、回滚失败和审计异常，不宣称 MCP 已连接。

批量矩阵作为库内高级入口保留，与详情共享相同的逐对勾选。勾选数量不是实际文件数量；物理文件数仅在后端预览后展示。

## 范围与存储

所有范围的条目都保留在列表中。切换全局/项目只改变可分发状态，避免看起来像丢失配置。
全局配置指当前用户跨项目，仍只作用于勾选的 Agent；此时隐藏项目目录。项目配置显示最近项目名称，点击可选择或手动填写绝对目录。
项目必须已存在；不沿用程序启动目录。取消系统目录选择不保存设置，也不改变当前目录。

侧栏配置库入口显示文件名，完整路径在管理对话框；目标实际路径在预览中始终可见。
切换库不会分发配置或覆盖旧库，可选择设为启动默认库。损坏的库不能当作空库覆盖。
设置保存在 `~/.mcp-hub/settings.json`；保存默认值不改变当前任务范围，新备份目录保存后生效且不迁移历史备份。

## 视觉与信息层次

浅色侧栏、灰白工作区、单一青绿色主操作，统一线性图标与间距。常用入口突出，文件路径、原始结构、写入策略按需展开。
桌面列表按名称、适用范围、当前配置状态组织；选择后才显示详情，避免空三栏。小窗口折叠侧栏文案，详情移到列表下方。
状态同时使用文字和图形；表单和按钮保留键盘焦点指示，减少动态效果时关闭转圈动画。

## 验证与已知边界

所有测试和构建在 GitHub。`CI` 覆盖 Rust、原生桌面命令、前端单元测试、构建和 Chrome 交互。
`GUI review` 在 macOS Chrome 复用交互流程并上传中文字体截图，包含配置库、详情、编辑、Agents、导入、预览、设置、历史、首次使用和小窗口。
浏览器使用内存 IPC fixture，不代替真实桌面目录选择、系统凭据权限或真实 MCP 连接验证；这些仍需安装包使用环境核对。

本轮保留现有保存、备份与分发协议。分发确认仍重新计算文件内容，没有绑定预览时的配置库内容快照；确认前应避免外部并发修改。
导入沿用已有源/目标快照和一次性预览校验，详见 [导入说明](IMPORTING.md)。编辑保留已有高级字段，但本轮未新增全部高级字段的可视化编辑。

v0.4.0 不升级依赖、不迁移用户文件格式。回退代码可在 dev 上 revert 本次提交，再由 GitHub 验证；已保存的兼容配置与设置继续可用。
如需恢复具体配置内容，在变更历史核对备份和影响路径，另存后续编辑，再明确确认恢复。

# MCP Hub 界面方向：配置工作台

本轮只提供设计原型，不替换正式 GUI，不连接真实配置。打开 `ui-workbench.html` 可比较两个视角，
体验选择、读取来源、模拟导入、查看详情、选择目标和预览确认。所有数据仅在页面内存中变化。

## 要解决的使用问题

目前的界面把用户直接放进十四列矩阵：必须先知道清单是什么、准备文件、理解作用域，再决定每一格。
“已有配置”藏在环境检测里，与配置库分离；保存清单、选择分发和确认写入也容易被误认为同一步。

默认界面改成围绕一次配置任务组织，矩阵降为高级批量入口。侧栏只保留「配置工作台、Agent、变更记录」，
把环境检测放进 Agent 的详情，把备份和回滚放进变更记录。默认只突出一项主操作。

## 两个视角，一份任务草稿

- **按 MCP**：适合把几个 MCP 分发给多个 Agent。左侧配置列表，中间详情，右侧目标 Agent。
- **按 Agent**：适合确认某个 Agent 已经配置什么。先选择 Agent，查看来源路径和已有条目，再选择导入配置库。
- 顶部显式显示工作目录和作用域。项目级必须选目录；用户级与项目级切换后重新计算路径和预览。
- 底部一直显示本次选择的 MCP、Agent 和实际目标文件数量，主按钮为「预览变更」。
  文件数按物理路径去重，不能用“配置数 × Agent 数”推算；共享文件必须说明共同可见的后果。

## 从安装到第一次完成

1. 无清单时给两个入口：「从已有 Agent 读取」和「创建空白配置库」。不要求用户手工创建 YAML。
2. 读取默认只读，逐条展示名称、类型、来源和脱敏信息。原始密钥不从后端回传。
3. 用户明确选条目后才导入；后端重新读取原文，把可识别字段转成统一模型。
   无法安全转换的字段展示为待处理项。密钥要求映射到环境变量，不能把脱敏占位符写进配置库。
4. 同名冲突逐条选择跳过、重命名或替换；任何替换都先展示差异，不默认覆盖。
5. 选择目标、核对作用域和实际路径，预览新增/修改/跳过/冲突，确认后才写入。
6. 结果分别显示成功、未变化、已恢复、回滚失败、审计异常。显示“配置已写入”，不宣称 MCP 已连接。
   后续可增加显式的握手、工具发现和只读调用验证入口。

## 视觉与编辑行为

浅色工作区、低对比导航、单一强调色，状态通过图标和文字共同表达；避免整屏彩色圆点。
不默认展示长路径和原始 JSON，放在详情中按需展开，但预览中始终可见目标路径。
参数编辑改为每个参数独立一行；环境变量使用键值表，避免逗号拆分破坏原值。
未保存的编辑保留为草稿，切页时提示；保存到配置库和应用到 Agent 使用不同文案和按钮。
配置路径、作用域和项目目录属于工作上下文，应记住最近选择。

## 建议实施顺序

先完成安全修复验证，再做首次启动和项目目录选择；随后串联读取与导入；最后调整工作台布局。
导入、上下文持久化、项目目录选择与完整工作台均是待实现功能，当前原型仅用于设计评审。
现有矩阵和清单文件能力保留，避免界面调整破坏已经使用文件管理配置的工作方式。

# MCP Hub v0.4.3

改善 macOS 图形界面的安装体验，并调整发布产物名称，便于区分图形界面与命令行。功能、配置库和软件设置格式与 v0.4.2 相同，无需迁移。

## 本次变化

- macOS 应用改为 ad-hoc 签名（`bundle.macOS.signingIdentity = "-"`）。下载后不再提示“已损坏”，首次打开无需在终端执行 `xattr`。
- 发布构建会挂载 DMG，并用 `codesign --verify --deep --strict` 检查其中 `MCP Hub.app` 的签名和资源封装，校验不通过则停止发布。
- macOS 图形界面安装包由 `MCP.Hub_<版本>_aarch64.dmg` 改名为 `MCP.Hub_<版本>_macos-arm64.dmg`。
- 三个平台的命令行包由 `mcp-hub-v<版本>-<平台>` 改名为 `mcp-hub-cli-v<版本>-<平台>`，避免与图形界面混淆。Windows 安装程序与免安装 ZIP 名称不变。
- 产物名称统一由 `scripts/publish_release.py` 生成；v0.4.2 及更早版本仍按原名称校验，可继续恢复中断的发布。
- 更新 README 中的 macOS 下载与首次打开说明。未新增或升级依赖。

## macOS 首次打开

1. 打开 `MCP.Hub_0.4.3_macos-arm64.dmg`，把 **MCP Hub** 拖入「应用程序」。
2. 首次双击会提示 Apple 无法验证开发者，点「完成」。
3. 打开「系统设置 → 隐私与安全性」，在安全性部分点「仍要打开」并确认。之后可直接启动。

ad-hoc 签名不是 Apple Developer ID 签名，也未经过公证，因此首次打开仍需手动放行一次。命令行包解压后双击会打开终端，这是正常行为；需要图形界面请使用 DMG。

Windows GUI 仍未签名，需要系统已有的 [Microsoft WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。配置、设置和备份保存在用户目录及自定义位置，与 v0.4.2 共用。

## 验证

测试、依赖恢复和构建在 GitHub Actions 执行：Windows/Linux Rust、前端测试与浏览器回归、Windows 桌面编译、发布恢复与免安装打包测试、三平台 CLI 冒烟、Windows/macOS GUI 构建、DMG 内应用签名校验，以及最终资产集合与校验清单检查。
CI 签名校验确认应用已完整签名，不等同于在目标 Mac 上的启动验证。

检查通过后经 PR 合入 master，为已进入 master 历史且与主干文件树一致的候选提交创建标签，复用同一批已验证产物发布。
下载后使用 Windows `Get-FileHash -Algorithm SHA256 -LiteralPath '<downloaded-file>'` 核对清单；Linux/macOS 可使用 `sha256sum --check SHA256SUMS` 或 `shasum -a 256 -c SHA256SUMS`。

## 升级与回退

macOS：退出旧版后用新 DMG 中的 **MCP Hub** 替换「应用程序」中的旧版本。Windows：关闭旧程序后安装新版，或将 GUI ZIP 解压到新目录运行。本版没有格式迁移。
需要回退时重新安装 v0.4.2；v0.4.2 的 macOS 应用未签名，首次打开可能需要执行 `xattr -dr com.apple.quarantine "/Applications/MCP Hub.app"`。

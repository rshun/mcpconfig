# 从 Agent 导入配置库

导入只修改统一配置库，来源 Agent 文件保持不变，也不会分发配置、启动 MCP 或创建系统环境变量。

## 操作

1. 侧栏「当前配置库」指定目标配置库的绝对路径。文件可以尚不存在，确认导入时会新建；已有文件必须是有效的配置库。
2. 选择全局或项目范围。项目范围必须先选目录，导入条目保留来源范围，不自动改为 inherit。
3. 在 Agents 页点选 Agent，核对来源文件，点击「导入到 MCP 库」。后端重新读取来源，不使用只读页面中的脱敏值。
4. 勾选需要导入的条目，处理同名项，为隐藏字段填写环境变量名。
5. 点击「预览导入」，核对目标路径、条目名称、变量引用及原条目的字段结构。修改选择后必须重新预览。
6. 有替换操作时额外勾选替换确认，再点击「确认导入配置库」。写入前备份原配置库，完成后自动返回「我的 MCP」，刷新配置库和备份列表。

同名项默认跳过，可选择「重命名新增」或「替换同名项」。重命名不能覆盖已有名称，批次内名称也必须唯一。
替换会覆盖同名条目的完整模型，包括原来的平台覆盖、标签和其他字段；不会替换未选中的条目。
比较按配置库原有的大小写敏感名称规则进行。不隐式合并同名条目，也不自动追加数字改变名称。

取消、空选择、全部跳过或预览失败不写入任何文件。损坏的目标配置库不会被当作空库覆盖。
不支持的字段、非字符串参数或环境变量、有歧义的别名、多个认证来源及非 Bearer 认证会阻止对应条目导入，
可继续选择其他可转换条目，不静默丢字段。JSON/JSONC/TOML 采用来源实际文件的格式和 MCP 根节点。

## 敏感信息与变量

v0.4.2 起采用与已有配置查看、分发差异一致的选择性脱敏规则。来源完整原文只在后端内存作一致性检查，不写入草稿文件。
扫描显示条目名称、传输类型、冲突状态和凭据字段名；预览正常展示普通配置，原始凭据在离开后端前隐藏。

- 普通 URL（含非敏感查询参数）、包名、可执行文件路径、工作目录和参数保留原值，不需要环境变量映射。
- `PATH`、`NODE_ENV`、`API_BASE_URL`、`Accept` 等普通环境变量/请求头直接导入；`API_KEY`、`clientSecret`、`PASSWORD`、
  Token、Cookie、私钥、认证头等按字段语义隐藏。`MAX_TOKENS`、`--tokenizer` 等名称不按 Token 凭据处理。
  `PASSWORD_FILE`、`TOKEN_PATH`、`--token-file` 等明确表示文件或目录的字段也保留路径值；值内另含可识别凭据时仍隐藏。
- `--password value`、`--api-key=value` 等敏感选项、Bearer/Basic 值、URL 用户认证部分和敏感查询参数
  （包括百分号编码的参数名）、私钥文本及常见凭据格式会触发隐藏。识别到凭据的字符串整体隐藏。
- URL 或完整命令字符串内含凭据时，整个字段需要映射为完整值；独立参数只映射其值。
  `--token=value` 导入为 `--token=${ENV:MY_TOKEN}`，保留选项名。

普通配置的展示和导入不再依赖固定命令白名单。规则不能可靠识别任意自定义名称下的任意字符串；
例如没有敏感名称或可识别格式的自定义字段会原样显示。请把凭据放入明确的敏感字段或使用变量引用。

填写的是变量名，例如 `SERVICE_API_KEY`，不是变量值。名称只能使用 ASCII 字母、数字和下划线，不能以数字开头。
除 Bearer 映射为 `auth.token_env` 外，隐藏字段写成 `${ENV:SERVICE_API_KEY}`。
已有的完整 `${VAR}`、`${ENV:VAR}`、`${env:VAR}`、`{env:VAR}` 引用会归一化，
完整 `${HOME}`、`${PROJECT_ROOT}` 等内置上下文引用保留语义；不展开或读取进程中的变量值。
含变量引用的普通混合字符串保留，例如 `${HOME}/tools`、`Bearer ${ENV:SERVICE_API_KEY}`；仍含敏感字面值的字符串需要映射。
混合字符串中的 `{env:VAR}`、`${env:VAR}`、`${VAR}` 引用也归一化为 `${ENV:VAR}`，内置上下文变量保留原语义，保证后续跨 Agent 分发可解析。
Bearer 变量的值应是令牌本体，不含 `Bearer ` 前缀。

### 原样复制凭据（默认）

从 v0.4.4 起，每个识别到的凭据字段可在导入页选择「原样复制」或「映射环境变量」，默认「原样复制」，无需填写即可导入。

- 原样复制把来源 Agent 中的原值写入配置库：Bearer 写为 `auth.token`，URL、参数、环境变量和请求头保留原文；
  `--token=value` 等参数整体保留。原值只在后端内存中保存，不经过 IPC 返回前端。
- 扫描和导入预览仍只显示 `[已隐藏]`，避免截图或录屏泄露；已有配置查看与分发差异的脱敏规则不变。
- 配置库及其写入前备份将以明文保存这些凭据，审计日志不记录凭据值。请勿把配置库提交到代码仓库或分享给他人；
  需要共享配置库时，改用「映射环境变量」。
- 每个凭据字段必须且只能选择一种处理方式；普通字段不能借“原样复制”绕过校验。
- 配置库校验对明文 `auth.token` 给出建议改用 `token_env` 的提示，不阻止保存。

例如某参数原来含凭据，可映射为 `MCP_SERVICE_ARGUMENT`，导入后参数为 `${ENV:MCP_SERVICE_ARGUMENT}`。
需自行在运行 MCP 的环境中配置其值。导入成功仅表示配置库保存成功，不代表变量已设置或服务已连接。
后续分发仍使用项目已有的变量解析和各 Agent 凭据策略，分发前应核对预览与目标环境。

## 预览一致性、失败与回退

每份草稿有效期 10 分钟，最多同时保留 8 份，每个输入文件限制 4 MiB。取消或关闭页面会请求释放草稿，退出软件后内存草稿不保留。
配置库目标不能是任何内置 Agent 的已知配置路径（包括当前项目的候选路径），也不能是软件设置或审计日志。
确认只提交后端预览 ID，前端不能直接提交一份修改后的原始配置。每次新预览使该草稿的旧预览失效，确认只能执行一次。
来源内容、来源候选路径优先级、文件实际目标、配置库原文、项目上下文或软件设置变化，都会阻止旧预览提交。
重新扫描后再预览；失败确认会消耗该预览，可取消导入再重新打开。配置库保存入口还会再次检查原文基线。
这些检查不提供跨进程文件锁，请避免确认保存期间由其他软件同时改写文件。

备份失败则不保存配置库；写入或校验失败沿用原子写入和回滚机制。审计失败时配置库可能已经保存，会明确显示警告，不能简单重复导入。
在「变更历史」核对配置库路径和写入前记录后可回滚。回滚会覆盖后续编辑，需先另存这些编辑；原配置库不存在时恢复会撤销新文件。
备份含原配置库原文，可能包含历史凭据，请妥善保管。导入草稿不会额外备份来源 Agent 文件。

## GitHub 验证

所有测试和构建在 GitHub Actions 执行，本地不安装依赖、不构建、不运行测试。
后端使用隔离目录和占位符，覆盖三平台 14 个适配器、本地/远程转换、原文备份、同名处理、敏感值隐藏、变量引用、
损坏与有损输入、重复选择、取消、重复确认、陈旧预览、来源优先级、上下文变化和保存失败。
前端测试核对 IPC 载荷；Chrome 真实页面回归覆盖默认跳过、重命名、替换确认、取消、编辑后失效、陈旧提交和导入后重新加载。
选择性脱敏回归覆盖普通配置可读、无凭据导入无需映射、混合配置仅映射凭据、敏感参数、变量引用及敏感变更标记。
浏览器模拟 IPC 负责交互验证，真实磁盘和导入会话规则由 Rust 测试验证，Windows 桌面检查负责验证 IPC 注册和类型。

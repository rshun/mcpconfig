# 安全修复与验证

本轮在 dev 修复六项高优先级问题，不修改已发布标签，不新增依赖。

## 写入边界

- 先按规范化的真实文件路径合并计划，每个文件只备份、写入一次。共享文件中的不相交条目合并；
  同名 MCP 的最终内容不一致、读取期间内容变化、格式冲突或某计划被阻止时，整个文件停止写入。
- 共享同一个 MCP 容器的 Agent 会共同看到其中的条目。预览会提示这一事实，不能保证共享容器内按 Agent 隔离配置。
- 引擎拒绝未合并的重复写入计划；写入前检查目标是否与计划基线一致，变化后要求重新预览。
  这不等于完成“预览到确认”的内容锁定：GUI 确认仍会重新计算计划，也未对外部程序提供文件锁。

## 备份与失败结果

- 备份目录包含时间、纳秒、进程号和计数，使用排他创建；遇到碰撞重新分配，不复用目录。
  原文和 manifest 在任何实际配置写入前写入并同步到磁盘。
- 写入失败后恢复原文件或撤回新文件，并检查恢复结果。成功恢复是 `failed`；
  恢复失败是 `rollbackFailed`，回执提供备份位置，GUI 不再笼统宣称“已自动回滚”。
- 审计失败单独记作 `auditFailed`，成功写入的配置保留，明确提示未回滚。
- 旧版备份仍可以读取和恢复。Windows 备份沿用用户目录 ACL，当前没有额外的 ACL 收紧实现；
  不应把 Unix 的 0700/0600 权限承诺直接套用到 Windows。

## 清单保存

清单保存移入应用层和 IO 引擎：校验 → 唯一备份 → 原子替换 → 校验 → 必要时回滚 → 审计。
备份失败时停止保存。JSON 扩展名保留 JSON 格式，其他清单保存为 YAML。
清单备份进入现有「备份回滚」列表；审计异常作为保存警告持续显示。

## 展示与格式

- 查看、GUI 预览及 CLI diff 复用核心脱敏规则，只展示本次 MCP 条目的结构化差异。
  参数、地址、环境变量、headers 和未知字段值不输出；敏感值改变时使用固定“原值/新值”标记，
  不输出原值、摘要或源文件其他区域。实际配置写入仍使用原始值。
- JSON/TOML/YAML 解析错误不回传源码片段，避免错误日志泄露凭据。
- VS Code 的 `.vscode/mcp.json` 和用户配置 `mcp.json` 使用 `servers`；
  项目 `.mcp.json` 与用户 `mcp-config.json` 使用 `mcpServers`。
  规划、检测、矩阵和只读查看都按实际文件判断，不能只按 user/project 判断。
  含注释的 VS Code 原生文件默认受 JSONC 保护；GUI 目前没有允许去除注释的开关，因此会停止该文件的写入。
  格式依据：[VS Code 官方配置参考](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)。

## GitHub 验证与回退

本地不构建、不恢复依赖、不运行测试。推送 dev 触发 `.github/workflows/ci.yml`，
执行 Windows/Linux 后端测试、前端测试、真实浏览器回归和 Windows 桌面编译。
新增用例覆盖共享文件合并与冲突、四种 VS Code 路径、注释保护、清单备份恢复、并发唯一备份、
备份失败、损坏内容恢复、回滚失败、审计失败、陈旧计划和展示脱敏。
用例均使用隔离临时目录和占位符，不读写真实用户配置。

发生 `rollbackFailed` 时先保留回执指向的备份，停止再次应用，检查对应文件；
不要把部分失败理解成整个批次已经恢复。需要恢复已完成的变更时，核对备份路径后使用「备份回滚」。
代码回退在 dev 对本轮提交执行 `git revert <commit>`，不删除备份、不移动已发布标签。
